# Generate Android State-Transition Tests

Use one canonical transition contract as the semantic truth. Android test code is an adapter to that contract; upstream unit tests and source-pattern observers are supporting diagnostics, not the benchmark definition.

## Inputs And Outputs

Start from `$explore-skill` artifacts plus the Android base/final refs. Read [transition-contract.md](references/transition-contract.md) and [agent-evaluation.md](references/agent-evaluation.md).

Produce:

- `transitions.json`: platform-neutral `given -> event -> expected` cases with evidence and stable digests.
- Android evaluator adapter/tests owned outside the candidate workspace.
- normalized `base.json`, `final.json`, and `agent.json` result files.
- a benchmark summary containing only code generation, compile, and semantic testcase metrics; keep transport, adapter, and provider failures in diagnostics.

Build a canonical contract from a reviewed draft instead of hand-writing digests:

```bash
python3 scripts/build_transition_contract.py \
  --input transitions.draft.json \
  --output transitions.json
```

## Workflow

1. **Trace behavior before writing tests.** Compare base and final production code and final tests. Identify state holders, events, effects, persistence/SDK calls, rendering, asynchronous completion, and rollback or cleanup. Resolve every scored boundary value, enum member, default, and capacity from final production code and corroborate it with an upstream test when one exists; record the source path and symbol in task evidence instead of inferring a plausible value.
2. **Define the canonical transitions.** Give each case a stable ID and atomic `given`, `event`, `expected`, plus invariants and evidence. Cover initial state, success, failure, cancellation, retry/timeout, persistence/restoration, and cross-surface propagation when the feature has them.
   - Before freezing the contract, establish each `given` through the real production API. Do not inject derived values (for example computed bitrates) that the implementation does not accept as inputs. Keep a reachability trace or explicit input-domain audit for such cases. If a frozen expectation contradicts immutable upstream runtime behavior, retain the failing assertion and evidence until a reviewed, versioned contract correction is authorized; do not modify production or broaden accepted values to force polarity.
3. **Separate changed from unchanged semantics.** Every scored case must be final-positive and must fail on base for a semantic reason. Put unchanged regressions in a non-polarity diagnostic suite.
4. **Generate evaluator-owned Android tests.** Prefer runtime state/effect/UI observation through a narrow adapter. Keep fixtures deterministic. For every effectful transition, verify that the implementation is wired into the production entry path; an unused persistent store, repository, presenter, or UI component is not semantic evidence. Do not let candidate code select outcomes by testcase ID, return oracle facts, or read evaluator files. Compile adapters independently per class or case so one API mismatch cannot hide unrelated results.
   - Audit the base-to-final production delta against the test-double boundary. Do not replace a new or modified application-owned SDK bridge with an application-interface fake. Execute that bridge and its mappings/side effects against external SDK leaves, preserving connected original-page ownership; retain narrower UI/domain evidence separately until the full path is proved. See the changed-bridge rules in [transition-contract.md](references/transition-contract.md).
   - Semantic benchmark scores require execution of the candidate's actual production state transitions. Source-pattern matching is diagnostic only, even when base/final polarity looks correct. If runtime execution is unavailable, report `not_scored` and incomplete validation; never fall back to source scores. Record runtime, before/after snapshots, invoked production methods, external-boundary effects, assertions, and invariant checks for every case. Distinguish JVM/domain tests, transpiled ArkTS domain tests, native ArkVM tests, and device UI tests; do not infer UI or OS persistence from a domain-only run.
   - Verify the canonical `given` state was actually established before dispatch. An ignored setup setter or an unresolved-input fixture replaced with an immediate successful response is not a valid test of the requested transition. Specify async observation boundaries with held completions or controlled clocks. Preserve UI event eligibility: bypassing disabled controls through a presenter does not establish a user-visible failure. Record these as fixture/contract gaps until repaired, not model failures.
   - After the first isolated agent run, reconstruct its candidate from base plus archived patch and audit every `0/N` or `N/N` result. Bind alternate APIs to executable production transitions only when state, effects/persistence, failure recovery, and entry-path wiring are observable. Re-run base/final polarity after every adapter change. Never replace a failed runtime binding with source-pattern matching.
   - Do not mark a formal agent scorer ready until it accepts an arbitrary standalone candidate directory through an explicit source parameter and executes that candidate's runtime transitions. Fixed base/final paths, archived patches, project-name checks, filename-based role inference, and source-observer fallbacks are unready and must fail closed.
   - Before scoring a frozen agent patch, run a candidate-ABI preflight against both no-change and known-final controls plus one reconstructed arbitrary candidate. Compile or resolve every hidden probe import, constructor, event entrypoint, observer field, and external-leaf stub against the candidate's actual public surface. A missing or alternate candidate API is an evaluator binding defect and remains `not_scored` until the adapter is repaired; never infer a semantic failure from it or rerun model generation merely to change the API shape.
   - Keep evaluator dependencies outside the candidate dependency graph. A candidate may legitimately upgrade UI, compiler, or SDK dependencies while its standalone application still compiles; merging those dependencies into the hidden evaluator APK can create false DEX/link failures. Bind through a recorded public ABI or another detached runtime boundary, fail closed when no supported ABI exists, and classify evaluator-only dependency/link failures as `not_scored`, not application compile or semantic failure.
5. **Retain exact upstream JUnit only as diagnostics.** It is useful for source fidelity, but an API-shape compile failure is `adapter_failed`, not evidence that the semantic transition failed.
6. **Calibrate on immutable refs.** Run the same case IDs and transition digests against Android base and final. Require base `0/N` and final `N/N`, with no `not_scored`. Before publishing any agent score, also run an untouched-base no-change candidate and a known-final candidate through the exact arbitrary-candidate hidden pipeline used for agents; require the same `0/N` and `N/N` polarity. A final failure must first trigger a contract-to-source audit: correct any guessed constants or semantics before changing observer rules or migrated code. Repair the contract or adapter when calibration fails; never hardcode tag checks or markers.
7. **Run the agent candidate.** Use OpenCode with `minimax-token-plan/MiniMax-M3`, endpoint `https://api.minimaxi.com/v1`, and a 3600-second task timeout. Keep the API key in the user's OpenCode config or an environment variable, never in the skill, repository, prompt, logs, or result bundle. Allow subagents, constrain all exploration to the copied candidate directory, and provide only the public requirement and public transition inputs. Set both subprocess `cwd` and exported `PWD`/`OLDPWD` to the candidate. `external_directory: deny` is not sufficient when shell wildcards such as `ls *`, `find *`, or `cat *` permit absolute operands; deny those patterns and allow only fixed project-local commands.
   - Layer path-specific rules onto `read`, `edit`, `glob`, and `list`: allow relative paths, deny `/*`, then allow only the canonical candidate prefix. Audit completed tool inputs structurally; do not count permission-denied attempts as leaks. A completed candidate-external access invalidates that platform-task run.
   - Preflight outside agent timing: install the exact Gradle wrapper, resolve plugin/dependency mirrors, and prove the untouched base builds. Give the agent a candidate-local public init script when a mirror is required. Tell it to run the allowed build command exactly, without pipes or redirection.
   - Serialize all Android full application builds through `/tmp/long-term-benchmark-android-full-build.lock`. Serialize every OpenHarmony device runner through `/tmp/ltb-arkts-device-<sha256(serial)[:16]>`; do not create a second lock under platform-specific `$TMPDIR`. Hold the device lease from emulator launch through scoring and shutdown, and use the same explicit HDC port for launch, readiness, and evaluation. Lock waiting, build, device execution, and cleanup share the same task deadline. Refuse to start a disk-heavy build below 8 GiB free space and classify the resulting environment condition as unscored.
8. **Score once without semantic feedback.** Build diagnostics may be used for compilation repair. Do not reveal failing semantic cases to the agent or iteratively coach it against the oracle.
9. **Check discrimination and integrity.** Require all semantic cases to be scored and normally require `0 < agent_passed < N`. If an agent gets `0/N` or `N/N`, audit mutations, missing effects, production wiring, overly weak assertions, leakage, and task completeness. A class that implements the requested behavior but is replaced by an in-memory fake or never instantiated in the app must fail the affected transition. Do not tune expectations merely to force a middle score.
10. **Record and clean up.** Time from overall run start through the last task completion; do not separately add subagent time. Preserve prompts, versions, logs, diffs, build outcome, semantic rows, and digests. Export patches with newly created files included (`git add -N` before `git diff --binary`, or an equivalent method), then verify base plus patch reconstructs the scored candidate. In a multi-platform run, archive immutable platform-specific names such as `android-agent.patch`, `android-agent-generated-files.json`, `arkts-agent.patch`, and `arkts-agent-generated-files.json`; never let a later platform overwrite a shared `agent.patch`. Write a resumable manifest after every platform-task result. Bind each retained score to the matching log and patch; publish the manifest, calibration/rescore summaries, and reconstructable patches with the benchmark bundle. Bulky local logs may remain ignored, but publish their SHA-256 and byte length so the retained score is bound to an immutable local archive. When permissions or isolation policy changes, use a fresh run ID instead of reusing a checkpoint whose evidence was overwritten. Treat provider quota/auth/transport/runtime-packaging failures as `unavailable` diagnostics, exclude them from benchmark denominators, and resume them under the same model and conditions; never convert them to code-generation, application-compile, or semantic failures. Before deleting APK/HAP/HAR/APP/ABC/SO artifacts, record path, byte length, and SHA-256; retain only the hash manifest and assert that no binary remains. Remove stale agent files from published bundles when a newer run marks that platform unavailable. Remove build caches, temporary worktrees, unpacked archives, and duplicate candidates after archiving evidence.

Validate normalized results with:

```bash
python3 scripts/validate_result_matrix.py \
  --base base.json --final final.json --agent agent.json \
  --output validation.json
```

## Repository Integration

In Long-Term-Benchmark, regenerate tasks 08+ contracts with `scripts/generate_new_tasks_cross_platform_contract.py`, execute with `scripts/run_task_runtime_tests.py` and `scripts/run_runtime_transition_matrix.py`, and calibrate with `scripts/calibrate_new_tasks.py`. The agent runner uses the runtime entrypoint. `scripts/run_task_semantic_observer.py` and older portable source observers are historical diagnostics only. Publish metrics with `scripts/assemble_new_tasks_experiment.py` only after runtime calibration succeeds. Set `--agent-timeout 3600`. A skipped build has unknown compile status, never `passed`.

Do not report adapter/transport readiness as a benchmark metric. The published metrics are code generation rate, compile pass rate, and semantic testcase pass rate.
