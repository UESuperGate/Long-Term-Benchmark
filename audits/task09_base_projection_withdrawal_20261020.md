# Task09 Base Projection Withdrawal

The old ArkTS base suite physically opened the common Spaces tab and observed
the unavailable page. It then invented lifecycle post-state from `absent[spec.key]`
and marked an invariant false without executing that invariant's transition.
The real prefix is useful evidence; the projected post-state is not.

The current public validator and Task09 independent verifier reject that shape.
Existing evidence is retained, not rewritten into a successful calibration:

- `experiment_results/runtime_transition_20261020/task09_minimax_semantic_repair_v2/base.runtime.json`
  SHA-256: `b235d494cf94decc040571f9f20035e4717e5cc54bd3b376c41a28054a3fc988`.
- Original `state_tests/runtime/arkts/native/task09_strict/Task09Suite.js`
  SHA-256: `d086d0b8c34f6d31f65bdc0b46fa5bd9abbb74f5cdbf9a081b22dcc5c18425de`.
  Its generated copies and hashes remain in the corresponding build reports.
- The already-running v3 base replay uses the same old projection and cannot
  establish current calibration even if all nine native rows say `fail`.

The replacement requires a fresh candidate, physical enabled-tab click, original
presenter receiver transition, and the actual unavailable surface in the same
candidate window. Later canonical post-state remains null and every unchanged
invariant remains explicitly unevaluated. Transport, fixture and packaging
failures cannot establish a semantic missing-entry failure.

`task09_arkts_entry_evidence.py` defines the narrow source-bound policy. It is
not a completed device calibration: a fresh suite run and independent validation
are required before accepting new base results. Agent patches, production code,
canonical expectations and original failure evidence are unchanged.
