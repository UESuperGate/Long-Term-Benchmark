# 多选投票创建、编辑与投票（Android v26.08.4 -> v26.09.1）

## 任务定位

将 Element X 的单选投票扩展为完整的多选投票能力。实现必须贯通投票创建、编辑恢复、答案数量变化、时间线投票状态、用户选择、SDK 提交和失败恢复，不能只在界面上增加一个“最大选择数”字段。

## 版本边界

- base: Android `v26.08.4`，投票的最大选择数固定为 1，响应动作只接收一个 answer ID。
- final: Android `v26.09.1`，用户可设置大于 1 的最大选择数，并提交多个 answer IDs。
- ArkTS base/final 必须复现同一功能边界，使用同一组 canonical state transitions。

## 功能要求

- 新建投票默认最多选择 1 项，允许在答案数量范围内调整最大选择数。
- 删除答案后，如果最大选择数超过新的答案数量，必须立即收敛到合法范围；最小值始终为 1。
- 编辑已有投票时必须恢复其问题、答案、公开/不公开类型和最大选择数。
- 保存新建或编辑投票时，最大选择数必须作为真实 SDK payload 传递，不能只保存在 UI。
- 用户可在达到上限前选择多个答案；达到上限后，未选择答案不可继续选择，已选择答案仍可取消。
- 取消一个答案后应重新开放其它答案；提交时保持选择顺序并一次发送全部 answer IDs。
- 提交失败时保留当前选择并显示可重试状态；不得静默清空选择或伪造成功。
- 已结束投票保持只读，公开/不公开投票原有的结果可见性不被改变。

## 非目标与回归约束

- 不新增排名投票、权重投票或超出 Android final 的投票类型。
- 不改变结果百分比、胜者判定、投票结束和编辑权限语义。
- 不允许用版本号、testcase ID、marker 或 evaluator 文件决定运行结果。

## 验收口径

候选实现必须同时具备表单状态、上限收敛、编辑恢复、多选交互、SDK 多 ID 提交和失败恢复。仅渲染一个 stepper、仅把单个 ID 包成列表、或只让 final 目录返回预置结果均不算完成。
