# 全局搜索最近查询与房间历史（Android v26.09.2 -> v26.09.3）

## 任务定位

为 Element X 全局搜索增加可持久化的最近记录。实现需要把查询和房间两种历史条目贯通到 presenter、存储、房间资料解析、搜索界面和恢复路径，而不是只在当前页面内保存一个字符串数组。

## 版本边界

- base: Android `v26.09.2`，全局搜索支持房间/消息结果，但没有最近记录状态和持久化存储。
- final: Android `v26.09.3`，支持最近 query/room 记录、去重置顶、容量限制、持久化、清理和损坏恢复。
- ArkTS base/final 必须复现同一功能边界，使用同一组 canonical state transitions。

## 功能要求

- 打开空查询的搜索页时异步加载最近记录；没有记录时展示稳定空态。
- 键盘搜索动作只保存非空白 query；打开房间结果时保存 room ID。
- query 和 room 使用类型化条目，不得因字符串相同而互相覆盖。
- 重复条目移动到列表首部且不重复；总数超过 25 时丢弃最旧条目。
- 每次更新都同步持久化，重新创建 store 后能按原顺序恢复。
- 清理历史同时清空内存状态并删除持久化内容。
- 持久化内容损坏时返回空历史，后续新增条目仍可恢复正常工作。
- 加载 room 历史时解析当前 room info；已不可访问的房间被过滤，不影响其它条目。
- 选择 query 历史后填充搜索框、切回房间搜索目标并进入 loading；选择 room 由正常导航处理，不改写 query。

## 非目标与回归约束

- 不改变服务端搜索排名、分页阈值、消息结果映射和 feature flag 行为。
- 不持久化消息正文，不跨账号共享历史。
- 不允许用版本号、testcase ID、marker 或 evaluator 文件决定运行结果。

## 验收口径

候选实现必须覆盖 presenter 事件、类型化模型、并发安全存储、排序去重、容量裁剪、磁盘恢复、损坏恢复和 UI 选择行为。仅在界面上展示静态“最近搜索”列表不算完成。
