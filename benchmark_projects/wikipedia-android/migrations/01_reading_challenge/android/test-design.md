# Android runtime design

The API 37 instrumentation episode strongly links `ReadingChallengePageActionPrefix`. Every case enters that application-owned owner; enrollment delegates to `ReadingChallengeEnrollmentAction`, article reads delegate to `PageLoadCompleteActionPrefix`, and the final role reaches the unchanged `ReadingChallengeWidgetRepository`.

`given` writes only the SharedPreferences-backed leaf and evaluator clock, then reopens the store before observation. State names and streaks come from the production owner snapshot. Heartbeat and widget effects come from the controlled delivery log. The evaluator contains no repository fallback, source inspection, state transition model, or hard-coded availability verdict.

The base owner has the same ABI but only the pre-feature page behavior. Missing candidate APIs therefore fail binding instead of receiving a base-like semantic result. Formal calibration requires API 37 base 0/10 and final 10/10 with zero unscored cases. Raw device episodes are retained beside each scored report.

The visible scaffold only declares an empty `src/main/java` candidate root; it never copies, replaces, or removes production sources. Hidden assembly follows the candidate's declared `main` Kotlin roots and copies only compiled production `.kt`/`.java` inputs, excluding evaluator, leaf, and test roots. The untouched clean-room base must therefore compile through both stages and fail semantically at 0/10 with zero unscored cases.
