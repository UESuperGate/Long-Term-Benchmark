# Reviewed Common Preview Closure Eligibility

The JSON fixture is NOT an oracle and does not return semantic pass/fail.
Its SHA256 is pinned independently in the live JS guard and Python public
conjunct. It limits which unchanged production closure is sufficiently reviewed
to interpret actual common-prefix execution as a missing version-bounded feature.
Unknown implementations are NS, never semantic failures from selector absence.

## Code Closure Review

The complete standalone input contains nineteen files, whose paths, byte lengths
and SHA256 are listed in the fixture. The full-input digest uses the same runtime
inventory algorithm as the source-parameterized runner, without the directory
name. Identical standalone base copies can therefore qualify as role=agent.
Source matching by itself grants only eligibility, never a scored result.

The actual compiled production closure contains exactly the nine pinned entries.
Index imports only AttachmentFeature; EntryAbility loads pages/Index, with the
page/module/resource configuration pinned. Index constructs AttachmentPresenter
with the original AttachmentGateway and renders the fixed attachment preview,
caption, original-send and send-state surface. AttachmentFeature has no imports.
Its send transition is synchronous caption forwarding through the original
Gateway, then Sending -> Done/Failure. Neither that closed class graph nor the
reviewed entry contains metadata/quality/fallback/prepared-media functionality.
This is an explicitly reviewed small closure, not an inferred pattern applied to
arbitrary candidate filenames, tags or symbols. An added source file, changed
code/resources/configuration, different compiled closure or renamed controls
cannot acquire missing-entry eligibility by retaining old IDs or commonPreview.

The fixture's report/build/layout receipts come from the previously completed
real API23 base runtime. It preserves the whole initial native UI tree projection,
including all containers, labels and interactive/noninteractive/hidden nodes.
Only bounds, runtime window/hierarchy IDs, focus and other listed non-semantic
transport attributes are volatile. Unknown nodes/attributes, added/duplicate or
hidden controls, changed text/types/IDs and disabled controls do not match.

## Runtime Required After Eligibility

Each scored missing-entry case must still have its own fresh production UI
execution, actual caption input/click, completed original send, and three complete
before/caption/after UI snapshots. The new independent conjunct checks these
against the original byte-retained observer report, build, layouts and command
logs. Source/compile/environment errors are not semantic failures. Final-only
post-states and invariants remain unevaluated in the common-prefix branch.

The existing common-prefix policy is preserved byte-for-byte; this fixture and
Task10-only conjunct add a restriction, not a replacement or weaker fallback.
Actual positive full-feature native execution (including the frozen M3 candidate)
does not use this common-prefix eligibility mechanism. Its real state assertions
and separately reviewed case009 prepared-path prefix remain unchanged.

## Conservative Scope

This is intentionally not proof that every unknown implementation lacks features.
Equivalent refactors or legitimate new architectures outside the reviewed closure
must be bound to real complete runtime transitions or remain NS. They must never
receive 0/N merely because private selectors/files/exports differ. Public routing,
readiness and model-result promotion remain parent-owned.
